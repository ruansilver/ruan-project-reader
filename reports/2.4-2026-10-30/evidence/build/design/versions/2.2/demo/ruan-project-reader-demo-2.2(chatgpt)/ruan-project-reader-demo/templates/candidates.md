# 候选记录模板

依据设计 2.2 §3、§5.1。把下列“候选记录”节放在所属模块文档中；它不是第二份独立候选数据库。占位行仅说明格式，不是项目事实，正式记录须替换或删除。没有行不代表没有候选，未知或无法解析的计数不得填零。

## 类别与事实调查

类别限于：事务锁并发、写库缓存状态、MQ异步后台、异常重试补偿、权限判断算法、配置分派、外部调用副作用、出向调用、其他。

前七类命中后必须解释或登记缺口，不能处置为“琐碎”；查证后影响很小的也记“本文已解释”并说明。

| 触发类别 | 至少核对 |
| --- | --- |
| 事务锁并发 | 进入与结束边界、顺序、冲突和失败 |
| 写库缓存状态 | 变更条件、对象、结果和失败影响 |
| MQ异步后台 | 发送／消费、交接、完成、回执和重试 |
| 异常重试补偿 | 触发条件、处理路径和最终状态 |
| 权限判断算法 | 判断依据、分支、拒绝和不同结果 |
| 配置分派 | 配置来源、分派规则和调用差异 |
| 外部调用副作用 | 契约、成功／失败及下游影响 |

从实际执行体和出向调用开始，必要时追踪一跳；一跳不是停止硬边界。重要行为在深层、去向不明或汇点反查指出遗漏时，继续调查或登记待办。薄包装／琐碎理由必须说明已读到的实际工作位置。

## 处置与必需信息

| 处置 | 必需依据或去向 |
| --- | --- |
| 本文已解释 | 本图节点或正文中的实际解释位置 |
| 模块引用 | 实际承接细节的模块链接 |
| 外部边界 | 我方调用及输入、外部契约、我方成功／失败／超时处理的证据；不要求掌握外部内部实现 |
| 琐碎 | 基于已读实际代码的简短理由；不得属于前七类或掩盖重要触发项 |
| 待核实 | 缺口与下一调查动作；可链接所属模块的未决详情 |
| 阻塞 | 已尝试方法、缺失依据、影响及重试条件；可链接所属模块的未决详情 |

本轮对设计§5.1的最小补充：待核实或阻塞候选指向现有模块或COVERAGE.md未决表中的原始任务记录，不因候选也出现该问题而重复计数。当前原始任务逐项计数、不去重；每项完成后更新其原始记录及候选处置，再重新派生STATE。候选“数量”及检查对象数仍按设计§5.1计算，不能与待办任务数混同。

“本文已解释／模块引用／外部边界／琐碎”才属于已处置；“待核实／阻塞／无法识别的行”属于未处置。无记录去向、依据不符、未检查或无法解析的候选不得算已处置。

合并行只允许来源范围清楚的同类琐碎操作；重要触发项须单独可追溯。候选集合至少覆盖出向调用、关键判断与出口、状态及副作用、异常路径。候选为空时也须填真实扫描范围、可重复方法、检查数量及未检查区域。

## 外部边界与叶子反证

- 用任意满足已知契约的黑盒替换外部系统，本层图文是否仍成立？若外部规则仍决定我方分支可达性、回调时序或状态变化而无依据，应为待核实或阻塞，不能把访问限制写成已核实边界。
- 已证叶子须本层已核实、全部候选实质处置，没有仍应独立成文档而未落实的内部阶段，继续下钻主要增加琐碎步骤；未处置数为0且限制为“无”。重要未知或未读到的关键去向不能认定为叶子。
- 发现新事实可重开；重开后状态退回“梳理中”。
