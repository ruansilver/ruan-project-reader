# Markdown、总览、图形与完成闸门

依据：附件《ruan-project-reader Skill 设计规范（2.2）》§7–8；候选与检查契约见 [check-format.md](check-format.md)。

## 1. 最小知识库（§7.1）

```text
project-map/
├── README.md                 # 阅读导航、少量已核实颗粒度锚点
├── modules/
│   ├── 00-总览.md            # 普通模块文档：顶层执行网络
│   └── ...                   # 各独立执行模块
├── STATE.md                  # 当前焦点、下一步与派生汇总
└── COVERAGE.md               # 范围、入口／汇点、盲区及整体闸门
```

README.md 不另设总览规则或图；可保留少量已核实的颗粒度正反例，供跨会话参考。

## 2. 总览是一份普通模块文档（§7.1）

总览节点对应 COVERAGE.md 已发现入口所属的主体流程。节点短注或正文列所含入口序号，如 E1、E3。每条入口记录须指向总览实际节点，否则标“未映射”并进入待办；多个入口可对应同一主体流程节点。

总览边**只表示已核实的跨流程交接**，如直接调用、消息发送与消费、状态写入后被定时扫描。独立入口不强行连接，不把导航线冒充执行边。

总览也遵守一图一短注、候选记录、check、状态闸门；但其候选记录**只登记跨流程交接，即图中的边**，每条记录发送端与对端位置。对端未找到、由配置决定或在范围外时，按 §3.3 记录待核实、外部边界或阻塞，不把未知交接当成已证事实。

入口仅保存在 COVERAGE.md，总览引用入口序号，不复制。下层模块承接内部执行细节。发现新入口或跨流程关系时及时回补，不把初版总览冻结成最终结构。

## 3. 模块文档最小内容（§7.2）

每个独立执行模块只有一份权威 Markdown，主体为**一张 Mermaid 执行图 + 逐节点中文短注**。头部固定两行，分别取一个值：

```text
状态：梳理中
限制：无
```

- 状态只取“梳理中 / 本层完成 / 已证叶子”。
- 限制只取“无 / 有”；“有”须指向阻塞项或限制说明。

其余至少包括：标题与职责、进入与结果边界、图注、必要规则与源码依据、下钻／引用／外部去向、候选记录、闸门记录、未决。状态为“梳理中”时，闸门记录可暂缺。普通执行步骤不必各建文件。

每个可见图节点，包括判断、异常、结果、外部引用，均对应一条 **节点 ID / 原标签 / 简短说明**。ID 不放进可见标签；短注约 20 字，原则上不超过 25 个汉字，更多规则放正文。

源码证据定位真实文件及符号／位置；无法证实的设计动机须标解释或推断。已标下钻／引用的节点提供实际链接，未建立则指向待办。

## 4. 绘图原则（§7.2）

1. **先事实后布局**：只画有依据的直接执行边，不混淆串行、分支、循环、并发和异步；入口应到达结果或明确的异步责任交接边界。
2. **主线清晰、少绕线**：优先稳定方向、短连线、就近引用、少外框。只有语义分组必要时使用 subgraph，不为排版制造关系。
3. **重复引用不等于重复执行**：可多处绘制同一模块的引用出现项以改善布局，但指向同一文档；真实汇合结果不能任意复制。
4. **不为美观藏事实**：图大时按独立执行职责下钻，不省略条件、失败、状态和结果。标签简洁，说明放短注和正文。
5. **尽力保证 Mermaid 合法**：有校验工具则检查基础语法；没有则人工自检并说明未自动验证。不建设复杂渲染平台。

Figma 仅是 Mermaid 的使用场景，不是实施或验收门槛。Skill 不主动调用 Figma、安装插件、截图或自动校验视觉效果。用户可提供截图与文字，由任一 AI 按普通反馈修图；涉及执行事实，再由本地核实。

## 5. 三种完成不得混用（§8.1）

| 完成概念 | 必要条件 |
| --- | --- |
| 本层文档完成 | 本层入口、关系、关键条件、出口、图注和依据已核实；重要内部环节在本文解释或有有效下钻去向；本地验收并保存。后代可仍在调查 |
| 模块已证叶子 | 本层完成；候选逐项处置及叶子反证通过；没有仍应独立展开却未落实的重要内部环节；未处置数 0、限制“无” |
| 本轮范围整体完成 | 正向入口、反向汇点、适用盲区、范围缺口已核对；必要下钻及跨图关系落实；未决都有真实处置，无关键未知被冒充完成 |

叶子具体判据见 [模块与颗粒度](modules-and-granularity.md)；暂时收敛不等于整体完成，见 [发现与覆盖](discovery-and-coverage.md)。

## 6. 每次状态切换的反向闸门（§8.2）

拟从“梳理中”切到“本层完成”或“已证叶子”，以及声明整体完成前，须对当前适用范围检查：

- **入口 → 结果**：逐条检查适用入口到结果或异步责任边界，列无去向与未映射入口。
- **源码 → 流程**：核对已发现调用和重要汇点，列无候选／正文定位、归属不明或证据不符项。
- **封装 → 隐藏环节**：用触发表和候选记录查概括节点，列未解释的重要阶段或出口。
- **未决 → 处置**：核对待核实、阻塞、限制的去向与必需信息，缺项回写待办。

状态切换前在模块写闸门记录；整体完成的记录写 COVERAGE.md，范围为全项目。固定表头与四行如下，省略号须换为实际结果：

| 检查项 | 检查范围 | 对象数 | 问题数 | 其中阻塞本层 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 入口 → 结果 | … | … | … | … | … |
| 源码 → 流程 | … | … | … | … | … |
| 封装 → 隐藏环节 | … | … | … | … | … |
| 未决 → 处置 | … | … | … | … | … |

四项缺一不可。不适用须在说明中写原因；没有问题也记录带计数的零结果，不能仅写“未发现遗漏”。发现的问题登记来源和下一步，派生待办。

“其中阻塞本层”不为 0 或 check 失败时，不得切换状态；修复后复检。脚本通过不替代本地源码核实。check 的未验证项须报告、人工核验；无法核验则保留待办或写入限制，不能冒称通过。

发现新事实或引用变化影响本层陈述时，重开模块：状态退回“梳理中”，原闸门失效，重新过闸后覆盖。

### 什么问题阻塞本层

某个未决若可能使本层图、短注、出口、后续衔接的已写陈述失真，或使本层职责所需的重要关系／出口缺失，就不得宣布本层完成。

父层只须核实子模块边界契约及本场景实际可达出口。已登记给子层、又不影响父层真实表达的内部未决不阻塞父层，但仍留在待办。外部边界同样接受黑盒契约检验；访问限制不能冒充已核实的外部行为。

## 7. 受限成果与停滞（§8.3）

还能通过源码调查的问题应继续调查或保留待办。确因权限、外部系统、资料或当前授权范围无法取证时，写清问题、已尝试方法、缺失依据、影响及重试条件，可交付带限制的阶段成果。

- 不把未知写成已证叶子，不因限制宣布范围整体完成。
- 有限制的模块，限制字段为“有”；状态可以为“本层完成”，但不得为“已证叶子”，且仍须满足本层闸门。

针对**同一阻塞问题，连续两轮**没有新增有效证据、经过核实的实质修订或新的可执行调查路径，视为停滞：报告卡点、原因和下一步，可转向其他工作或如实阶段性交付。计数变化不自动代表进展；不得为过闸编造分类，不因轮数强行判完成。
