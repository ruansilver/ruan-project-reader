# 颗粒度、候选与复用

## 调查与拆分

每层成文前，先沿实际执行体、调用及分派向下预研，直到证据足以解释本层行为、关键条件、结果、上下游与边界，再返回本层组织结构和陈述。可先列可修订的粗粒度线索引导调查；深度取决于证据需要，重要未知继续追踪或明确留待办。薄包装、琐碎的判断必须说明已读到的实际工作位置，名称或签名只能作为线索。普通取值、轻量判断可以内联，重要事实必须解释但不一定新建文档。

职责可命名、进入条件与主要行为明确、成功／失败／异步出口能说明，且抽象能帮助理解上层，才是合适的独立模块。多阶段任务、事务／状态／重试／异步边界、掩盖上层主线的片段或完整复用语义优先独立；不按代码目录、函数数量或固定深度拆分。模块可跨类、跨函数，没有永久层级或唯一父级。

## 事实触发表

以下命中项不得处置为“琐碎”；核实影响很小也写“本文已解释”及理由。

| 类别（记录固定值） | 至少查清 |
| --- | --- |
| 事务锁并发 | 进入、结束、顺序、冲突和失败 |
| 写库缓存状态 | 变更条件、对象、结果及失败影响 |
| MQ异步后台 | 发送／消费、交接、完成、回执和重试 |
| 异常重试补偿 | 触发、处理路径和最终状态 |
| 权限判断算法 | 判断依据、拒绝、分支和不同结果 |
| 配置分派 | 配置来源、生效选择、分派规则及调用差异 |
| 外部调用副作用 | 契约、成功／失败和下游影响 |

另有“出向调用”“其他”两类。类别按行为判断，不能把深层写库改名为出向调用以规避触发表。

## 有限候选逐项处置

实际检查后形成候选，至少覆盖出向调用、关键判断与出口、状态、副作用、异常。来源、数量、扫描范围和方法均可复查。没有行不证明没有候选；空集合仍记录扫描范围、方法、零对象及未检查区域。只有来源清楚的同类琐碎操作可合并；重要触发项单独追溯。

| 处置 | 必需内容 |
| --- | --- |
| 本文已解释 | 本图节点或具体正文定位 |
| 模块引用 | 实际承接细节的模块链接；核实边界与当前场景可达出口 |
| 外部边界 | 我方调用／输入、依据的外部契约、成功／失败／超时处理，包括确实未处理 |
| 琐碎 | 实际工作位置和代码理由，不属于触发类别、不隐藏触发项 |
| 待核实 | 缺口及下一调查动作 |
| 阻塞 | 已尝试方法、缺失依据、影响和重试条件 |

前四种才是已处置。无去向、未检查、证据不符或无法解析不能按已处置或零项处理。

外部边界用黑盒替换检验：换成任意满足已知契约的系统，本层图文是否仍成立？若外部行为仍决定我方分支可达性、回调时序或状态且缺少依据，记待核实或阻塞。访问受限不是外部行为已证实。

## 公共模块

先内联，有独立解释价值再提升。一次调用也可独立；专为复用抽取时通常须至少两个真实场景、完整共同执行语义和清楚的差异，仅共享少量语句或符号不够。

公共文档写内部行为、真实入口、参数引起的差异和全部重要出口。调用方各写本场景输入、适用分支、实际可达出口与后继，不把不可达出口画成可达，也不把调用者前后继固定在公共文档。无需维护全量反向调用清单；契约变化时按需搜索引用并复核。

父层核实子模块进入条件、结果、异步交接和本场景可达性；已由子层承接且不影响父层表达的内部未决不阻塞父层，但仍追踪。若影响本层陈述真实性或使职责要求的重要关系／出口缺失，则阻塞本层。

## 叶子反证

只有本层已核实、候选全部实质处置、没有仍值得独立成文档而未落实的阶段，且继续下钻主要增加琐碎步骤，才具备叶子的技术条件；标已证叶子还须按 [完成规则](completion.md) 取得当前版本用户验收与有效指纹。未处置数必须为零，限制为无；不要求只有一个函数或没有判断。新事实可重开，回到“梳理中”并使旧闸门失效。
