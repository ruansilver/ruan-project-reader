# design/：版本设计文档

这里存放 `ruan-project-reader` 每个版本的设计文档，是**目标版本的唯一权威**。AI 助手不会根据源码或安装目录猜测该开发哪个版本。

## 文件规则

- 新版本的文档放在 `versions/`，文件名等于版本号：`versions/1.2.0.md`。
- 新建时复制 `templates/version.md` 作为起点。`templates/` 下的文件只是模板，不代表任何真实版本。
- 版本号使用 `MAJOR.MINOR.PATCH` 三段数字（如 `1.2.0`）。
- 已发布版本的文档永久保留、不覆盖；升级时新增一份新版本文档，用 `previous_version` 指向上一版。

## 文档开头的元数据

```yaml
---
version: "1.2.0"
status: approved
previous_version: "1.1.0"
---
```

元数据只支持一行一个 `键: 值` 的简单写法（不支持嵌套和多行）。

| status | 含义 |
|---|---|
| `draft` | 草案。尚未确认，不会成为开发目标，也不能进入发布 |
| `approved` | 已确认，可作为开发目标。**不代表已实现、已验证或已发布** |

只有你可以确认版本：AI 助手不会擅自把 `draft` 改成 `approved`。若 1.3.0 是草案而 1.2.0 已确认，开发目标仍是 1.2.0。

## 一份已确认的版本文档应包含

为什么变更、完整目标能力、相对上一版的差异、技术设计、带编号的验收项（`R-001`…）、兼容性与已知限制。`templates/version.md` 已列好这些小节。
