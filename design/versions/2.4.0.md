# ruan-project-reader 版本 2.4.0 设计

## 1. 为什么做这一版

在源码核验后建立绑定具体图文版本的用户验收与独立继续授权，保证人工交接、文件传递和恢复可信。用户于2026-10-30已审阅并批准原始要求，授权按2.4正式版本登记、实施、验证，并在验收通过后交付；登记不表示实现或验收通过。

## 2. 完整目标能力

继承 [2.3.0](2.3.0.md) 的授权源码只读取证、先下研后成文、总览首轮、多方向发现、即时入口/汇点登记、候选逐条处置、父子/公共模块、四项闸门、串行维护、停滞与Goal安全边界。完整要求见 [用户批准的原始修复文档](2.4/ruan-project-reader-Skill-2.4-修复补丁-成稿.md) 全文；原文保持不变。原稿与继承规则有差异时按原稿及本次用户明确要求实施。

## 3. 相对上一版的差异

- 新增：待验收、每文件验收记录、排除式读者内容指纹、整体清单和指纹、规范版本与第九项汇总。
- 修改：完整稿以文件回传；本地核验通过后进入待验收，用户认可后转正，独立授权后开始下一项。
- 废弃：本地核验并保存即直接进入下一项的路径。

## 4. 核心流程与技术设计

本地取证→人工转交远端质疑→本地补证→完整稿文件回传→适用源码与闸门核验→待验收→用户认可当前指纹版本→等待独立继续授权。失败或需要修订回梳理中。每个人工节点保存现场并真正停止。

沿用现有 Markdown、模板和只读 check；采用标准库 SHA-256 与统一 ATX/围栏扫描。读者内容除六个操作性区块和顶部状态行外全部纳入；限制值纳入；正文不做Unicode规范化。范围路径NFC、UTF-8字节排序；每个模块先单独验收，总览同样适用。只在现有文件中记录，不引入状态引擎或自动通信。

## 6. 兼容性与迁移

无规范版本且为合法三状态/八统计的知识库按原静态规则只读检查，返回UNVERIFIED(2)，明确结构错误返回FAIL(1)。新旧混用不降级。迁移须用户明确指令，提醒知识库外备份，整库调整状态/记录/九统计，用户验收可分批。沿用既有技术记录时如实写当前核验基准；未知不假定不变；已知变化须补证。

## 7. 已知限制

Python3.10+或可信同算法计算能力是正式转正/整体完成的前提；不妨碍调查和草稿。静态工具不能证明真实用户授权、源码语义或历史撤销动作。真实Goal、双AI往返、长期恢复和平台加载分别实测或记录UNVERIFIED；关键验收未通过不得冒称全通过或自动发布。最终结果与发布决定记录于 reports/2.4-2026-10-30/，不进入Skill安装成品。本次未授权commit、push或Tag。
