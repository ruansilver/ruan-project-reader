# ruan-project-reader Skill 2.3 修复补丁

## 一 用户需求与修复边界

用户希望从真实源码建立可逐层阅读、核实和继续维护的 Markdown 与 Mermaid 项目知识库。每层先调查下层实际行为，再组织当前层文档；本地 AI 负责源码取证，远端 AI 负责独立质疑与完整图文，用户在明确的暂停点人工转交。交付应区分当前草稿、已核实内容、未决和完成状态。

本补丁用于指导本地 AI 修复**当前已经实现的 Skill**，不修改原版设计稿，也不重建另一套 Skill。采用最小化、无痕修改：保留有效结构、规则、模板与测试，只修补冲突、遗漏及执行断点。

最终 Skill 只保留简洁、正向的当前有效规则；修复原因、旧行为对照和修改记录只出现在本补丁或独立验收材料中，不进入 Skill 正文、引用资料、模板及示例。仅将实际实现中的现有版本元数据更新至 **2.3**；2.2 设计稿保持原样。

## 二 已观察的问题与证据边界

会话材料反映，本地 AI 曾持续生成模块与转交稿，却没有在需要远端质疑时形成有效的人工接力暂停点；待办曾被转述为由 20 增至 58。另有“13 条实际责任路由、7 条交接路由”因内部未读而未登记的自述，混淆了已发现入口与已展开流程。上述运行数字和行为来自聊天中对执行记录、本地 AI 发言的转述，尚未以完整日志和实际知识库独立核验。关于 Goal“最多 40 轮”的说法是上限，并非已执行轮数；补丁不依据未经核实的完成数量判断实施效果。

本补丁采用用户提供的 **《ruan-project-reader Skill 设计规范（2.2）》修订稿 `ruan-project-reader Skill 设计规范（2.2）(2)(2).md`** 作为目标规范：其 §4.2 含“首次协作以项目总览为对象”，§6 含人工转交后暂停（包括 Goal 续跑），§8.1 将完成 §6 双 AI 协作列为本层完成条件。实际 Skill 可能基于其他 2.2 文件或更早实现；须以其真实内容判断是规则缺失、规则冲突还是执行偏离。

## 三 先读实际实现 再定位修改

本地 AI 先读取实际 `SKILL.md`、所引用的资料、模板、检查器及现有测试，记录当前版本、工作区改动及已有测试结果；再将下列要求映射到**实际文件及条款**。本补丁不预设实现路径，不要求为了映射而新增文件、字段或状态系统。

可对照 2.2 设计的 §3.2—3.4、§4.2、§5.1—5.2、§6、§8—9。检查同一规则是否在入口指令、协作资料和模板中互相矛盾，统一为下述行为；保留无关内容，不修改被阅读项目的功能代码。

## 四 具体修复

### 1 每层先向下调查 再回到当前层成文

每一层都先沿实际执行体、调用和分派向下预研，直至足以解释本层的真实行为、关键条件、结果、上下游关系及边界，再回到本层组织可交付的图文。可以先列可修订的粗粒度线索以决定下钻方向，但当前层的结构与陈述须由下层取证支撑。核实依据是实际行为，而非名称、签名或机械停在一跳。深度随证据需求调整，不设固定三层，也不要求先完成全部后代文档；深层仍有重要未知时继续查证，或明确登记缺口，不能凭猜测写成事实。

父层须核实子模块的进入条件、重要出口、异步交接及本场景可达性；子模块全部内部细节并非父层成文的前置条件。

### 2 首轮以项目总览为协作对象

首轮按 §4.1 进行适用的多方向初步发现，记录扫描范围、方法、计数与未检查区域；针对主体流程、关键跨流程交接和本层边界开展足以支撑总览陈述的向下预研。随后返回总览层，形成 `README.md`、`COVERAGE.md`、`STATE.md`、`modules/00-总览.md` 草稿、源码依据、未决清单及单独转交提示词，达到可供远端质疑的程度即暂停等待人工接力。**首次转交不以全项目发现暂时收敛、全部下层模块成文或待办清零为前提**；未收敛和未核实部分如实标注，并保留后续检查去向。总览协作闭环后，再选具体流程、依赖或公共模块深化。总览中的流程与节点划分可随证据修订。

### 3 每轮范围明确 每次转交真实暂停

每轮处理一个当前模块或由真实执行关系关联、需要共同核验的子网，开始时明确协作对象、范围、共同处理的理由及本阶段交付物。为保证本层陈述正确而发现的新分支或下层关系，应继续必要的取证；其余新模块登记为后续待办，不自动扩大当前协作轮。范围不按固定模块数或调用层数裁剪。

顺序为：**本地取证 → 远端质疑 → 本地逐项补证回写 → 远端提交完整当前层文档 → 本地核验、检查并保存 → 下一项**。有实质疑点则继续补证，不以生成转交稿替代远端参与。

使用 Goal 等自动续跑方式时，其任务目标限于**当前自主协作阶段**，最近一次需要人工转交的节点即为本次执行终点。到达转交点，先保存草稿，在现有 `STATE.md` 的当前焦点与下一步写清协作对象、等待的远端材料类型及恢复动作，再将转交提示词单独放入明显的 Markdown 代码块，**结束本次自主执行**。首次质疑与后续完整文稿的转交均如此办理；只有用户带回相应远端输入后，才恢复对应阶段。

恢复时先读取实际文件与 `STATE.md`；等待事项仍未满足时保持等待。当前模式无法可靠在交接点停止时，应报告限制并停止使用该模式，可请求用户手动中止作为故障处置，随后改用能够明确结束于交接点的执行方式；这种手动兜底不视为自动暂停验收通过。无需建立额外状态引擎或自动连接两个 AI。

### 4 完成状态须有协作和源码依据

本层标为完成，须实际收到用户转交的远端质疑与当前层完整文稿，按需逐项补证回写，并由本地核验当前源码、边界、候选处置及适用完成闸门。使用现有记录定位已收到的远端输入、处理结果及尚存未决，供人工复核；不另建字段或状态。文件存在、转交稿已生成、计数对齐或 `check` 全绿均不能代替这些条件。阶段性草稿可保存，但必须如实保留待审、待核实或限制。

`check` 继续只检查机械可判定的契约；不能证明远端真的审查过、业务语义正确或源码已全部覆盖。只修必要的现有检查，不强迫新增字段或改变架构。

### 5 发现立即登记 未读不等于不存在

已知入口即使尚未展开，也须进入覆盖登记，标明未展开或未映射及下一步，派生为待办；不得为了保持映射完整而略去入口。重要汇点同样保留证据定位或未决去向。覆盖数量、零新增和待办减少不独立证明完成。

### 6 保留现有知识库和轻量机制

直接维护当前有效文档，不向知识库写修复历史。同一知识库串行写入，恢复以实际文件为准。待办按原始记录计数：多条记录指向同一模块仍分别核验、逐条消解，再更新派生汇总，不按目标模块去重。保留 Mermaid、逐节点短注契约、下钻链接及源码锚点。

不新增数据库、通用调用图引擎、固定深度策略、双 AI 自动通信或 Figma 实施任务；不借本补丁重设叶子判据及其他无关机制。

## 五 小型验收用例

在隔离样例中执行，保留现有测试。每项报告 **PASS / FAIL / UNVERIFIED**、实际证据和未验证范围，不能只复述期望。

| 用例 | 通过条件 |
| --- | --- |
| 总览与向下预研 | 样例把关键条件藏在深层调用，先读到必要条件再写父层；不必写完所有后代。完成可审阅的总览草稿即首次交接，即使全项目尚未暂时收敛；缺口有记录，未提前批量完成具体模块。 |
| 两次人工接力及范围 | 当前对象明确；发现无关新模块只登记后续待办。先交本地材料并等待，模拟用户带回远端质疑后才补证；第二次交接仍等待，带回完整当前稿后才核验保存。模拟输入明确标注，不能冒称真实远端审查。 |
| Goal 范围与恢复 | Goal 目标止于最近交接点；到达后本次自动执行结束。等待期间重新触发或中断恢复，仍保持等待、未新增模块或提前切换完成状态。不能可靠停止该模式时，本用例为 FAIL（未实际验证则为 UNVERIFIED）；手动中止不计 PASS。 |
| 完成闸门 | 文件齐全且机械检查通过，但缺本层实际远端闭环时，不能标为完成。 |
| 已知未读入口 | 提供已发现但未展开的路由，覆盖登记保留该入口及未决去向，待办正确派生。 |
| 重复待办 | 两条原始记录指向同一模块，逐条按源码消解，数量依次为 2 → 1 → 0，而非一次清零。 |
| 最小无痕回归 | 保留并运行现有有效测试；提供实际修改文件清单和独立的前后 `diff`，核对差异仅限必要规则、模板、检查及版本元数据。最终 Skill 呈现当前有效规范，无旧行为对照、修复过程叙事或无关新增机制；补丁中的限制性表述按语义自然融入，不机械照抄。 |

本补丁交付时尚未在实际 Skill 上执行上述验收，实施结果均为 **UNVERIFIED**。本地修复完成后，单独提交实际修改位置与 `diff`、每项测试的 **PASS / FAIL / UNVERIFIED** 及证据、未验证范围和剩余限制。自动交接或完成条件的关键用例若为 FAIL / UNVERIFIED，不得宣称 2.3 已完成验收。该报告独立于最终 Skill 保存。
