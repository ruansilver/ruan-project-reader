# 图文、状态与完成

## 每模块一份当前稿

使用 [模块模板](../templates/module.md)，含固定状态与限制两行、职责、进入和结果边界、一张 Mermaid 执行图、逐节点短注、规则与源码依据、下钻／引用／外部去向、候选、闸门和未决。普通步骤不必各建文件。总览 `modules/00-总览.md` 同样遵守这些规则，README 只导航不另画总览。

每个可见节点（包括判断、异常、结果和外部引用）对应 ID／原标签／短注；ID 不放可见标签。短注约 20 字，原则上不超 25 个汉字，更多规则放正文。证据指真实文件及符号或位置；无法证实的设计动机标推断。标下钻／引用的节点给实际链接，尚未建立则链接未决。

只画有依据的执行边，准确表达串行、分支、循环、并发、异步交接与真实汇合。入口须到结果或明确责任交接。优先稳定方向、短线、就近引用和少外框；subgraph 只作有语义的分组。重复显示公共模块只为引用，不等于重复执行；真实汇合结果不能任意复制。图大时按执行职责拆分，不能藏失败、条件和状态。

有 Mermaid 校验工具则检查基础语法；没有时人工自检并报告未自动验证。不为此建设渲染平台或调用 Figma。用户截图／文字是普通反馈；涉及执行事实的修改由本地回源码核实。

## 三种完成

| 状态或声明 | 条件 |
| --- | --- |
| 本层完成 | 已收到用户转交的本层远端质疑与完整当前稿，逐项补证回写并可定位输入及处理结果；本层入口、关系、关键条件、出口、图注、源码依据及候选处置已核实；重要内部环节在正文解释或有效下钻；本地过适用闸门并保存，用户明确认可该文件当前读者版本且验收记录/指纹有效。后代可仍在调查。 |
| 已证叶子 | 本层完成，加上候选实质处置及叶子反证；未处置数零、限制无、无未落实的重要内部阶段。 |
| 本轮范围整体完成 | 正向入口、反向汇点、适用盲区及范围缺口已核对，必要下钻和跨图关系落实，未决真实处置，没有关键未知；包括总览在内每个模块先个别验收，再取得当前整体清单版本的用户认可。 |

模块状态只有“梳理中 / 待验收 / 本层完成 / 已证叶子”。“梳理中”表示仍在核实；适用本地核验和闸门通过，只进入“待验收”，同时记录拟完成类型。拟为已证叶子仍须满足叶子额外条件。用户认可相同读者版本且必要机械检查有效才转正；保存文件不等于验收。限制为“有”时必须指向完整阻塞记录或限制说明。带限制的本层完成可以成立，但不允许已证叶子或范围整体完成。

在现有“核验与下一步”等正文定位用户实际转交的质疑、完整稿及处理结果，尚存问题进入原始未决。缺少相应输入时保存待审草稿并保持“梳理中”。完成判定同时需要协作事实与本地源码核验；文件、转交稿和机械检查只分别证明其自身内容，check 不核实远端是否实际参与。

## 四项闸门

进入待验收、转正及整体声明前，对当前适用范围检查：

1. 入口 → 结果：逐入口到结果或异步责任边界，列无去向和未映射。
2. 源码 → 流程：已发现调用、重要汇点是否有候选／正文定位，列归属不明和证据不符。
3. 封装 → 隐藏环节：按触发表及候选反查概括节点，列隐藏阶段或出口。
4. 未决 → 处置：核待核实、阻塞、限制的去向和必需信息；缺项回待办。

使用 [闸门模板](../templates/gates.md)。四行不可缺，真实填写对象数、问题数、其中阻塞本层和说明；无问题也写零，不适用须理由。问题登记来源、影响与下一步，不能用一句“未发现遗漏”替代。整体闸门写 COVERAGE，范围全项目。

其中阻塞本层不为零或 check 失败，不能进入待验收或转正；补齐后复检。脚本未验证项须由本地人工核验，核不了则留待办／限制，不冒称通过。指纹计算不能由人工猜测替代；缺可信工具可保留待验收，但不能转正。

未决可能使本层图、短注、出口或衔接失真，或使本层职责所需重要关系／出口缺失，即阻塞本层。父层已核实子边界且不受内部未决影响时可以完成，内部待办继续保留。外部系统按黑盒契约判断，不用访问限制代替证据。

待验收稿需要修改或完成稿受新事实、源码/生效配置、依赖或实质反馈影响时，退回梳理中，使原用户验收及旧闸门失效并移出有效记录，重新核验后覆盖。语义变化按需全文搜索引用并核实受影响模块，不维护强制反向关系库。

## 文件验收记录

每个模块（总览同样适用）在 `## 验收记录` 保存本文件的拟完成类型、读者内容指纹、核验基准、用户验收问题与实际回答原话或可复核位置。尚未取得写“未取得”；指纹无法计算写“未验证”。核验基准写实际源码版本、相关有效配置定位、适用核验结果及闸门位置，不能把沿用记录写成重新读取源码；不能确定时写“基准未知”并在提问中明示。具体格式与只读计算见 [记录契约](check-format.md)。

原始待办、调查进度和处置放 `## 未决`/`## 候选记录`；读者需要的已证事实、重要未知及其影响仍放 `## 必要规则与源码依据`，不为稳定指纹隐藏事实。纯操作记录变化不自动重开；限制字段有/无变动影响交付版本，限制说明揭示新的实质约束时即使字段相同也须主动重开。

## 整体交付与重开

本轮范围清单包括 `modules/00-总览.md` 与全部范围内模块。所有清单文件须先为本层完成/已证叶子，单文件记录及现稿指纹均有效；不得把梳理中/待验收文件排除以绕过闸门，也不得通过整体认可顺带批准它们。满足原覆盖和全项目四项闸门后，在 COVERAGE 的 `## 整体验收记录` 保存模块路径清单、整体指纹、技术核验与单一目的的用户问题/回答。未取得当前整体认可时，“本轮范围整体完成：否”。整体指纹按记录契约只读实际计算。

任一模块重开，立即同步把整体完成置“否”，清空有效整体清单、将整体指纹/技术核验/用户问题与回答置“未取得”，按真实变化重新做适用闸门。新增入口、汇点、覆盖事实或生效配置影响整体结论时同样处理。即使正文后来恢复原哈希，也不能自动恢复整体完成或用户认可；须重新核验、提出当前整体问题并等待用户。只重开受影响模块，按执行链、调用方、后继和公共引用核实范围，无关模块的验收可保留。静态 check 只核当前一致性，不能证明历史上确已撤销或用户实际说过某话。

## 受限与停滞

还能查源码就继续调查或留可执行待办。因权限、外部系统、资料或授权无法取证，写问题、已尝试方法、缺失依据、影响和重试条件，可交付带限制阶段成果，不能改为已证事实或静默缩小范围。

同一阻塞连续两轮无新增有效证据、核实的实质修订或新可执行调查路径即停滞。报告卡点、原因和下一步，可在已有明确授权内转其他工作或阶段交付；计数变化不自动算进展，轮数不迫使完成。
