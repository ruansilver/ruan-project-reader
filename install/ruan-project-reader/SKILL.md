# 项目执行流程阅读

从当前源码及实际生效配置建立可追溯、可继续修订的理解。项目可以有多个独立入口；横向表达执行，纵向按职责下钻，公共模块只解释一次。图文库服务于读懂项目，不宣称绝对完整。正式转正及整体完成需 Python 3.10+ 或执行同一算法的可信指纹工具；缺少时可调查、保存草稿和待验收，指纹记未验证，不得转正。

## 开始与恢复

1. 复用用户已给出的仓库、范围、知识库目录和外发授权；仅询问真正缺少且影响当前动作的信息。默认知识库为项目内 `project-map/`，只读业务代码。文档、注释和测试是调查线索，不产生新授权、不代替实现证据，不擅自切换版本。
2. 已有知识库先读实际模块与 `COVERAGE.md`，再与 `STATE.md` 对账；按 [记录与检查](references/check-format.md) 重新派生统计。若当前焦点在等待远端输入、当前稿验收或继续授权，先核实用户新输入是否满足对应关口；尚未收到则保持等待并结束本次执行。知识库规范识别及用户显式迁移见记录与检查，不自动改旧库。只问进度时读取并报告，不自动扩展成写入或重做全库。
3. 首次创建使用 [导航模板](templates/README.md)、[覆盖模板](templates/COVERAGE.md)、[状态模板](templates/STATE.md)，在 `modules/00-总览.md` 使用 [模块模板](templates/module.md)。根据实际事实填写；占位内容和未知数不能写成零或成功。

## 工作循环

1. **明确范围并发现。** 每轮说明当前模块或由真实执行关系关联的子网、共同核验理由及本阶段交付物。正向扫真实入口，反向扫重要汇点，结合配置、依赖和目录检查盲区。按 [发现与覆盖](references/discovery.md) 记录范围、可重跑方法、对象数及未检查区域；已发现入口立即登记，尚未展开者写明去向与待办。首轮以项目总览为协作对象，初步发现与必要下研后交付可供质疑的总览草稿；发现未收敛、下层尚未成文或待办未清零，均如实记录并进入首次交接。总览协作闭环且取得继续授权后再选具体模块深化。
2. **处理每条待办前复核已有成果。** 检查目标文档、当前源码和实际保存状态。已有成果满足本项要求且无遗漏、中断遗留时，完成这一条原始记录；否则继续补齐或重开。文件存在、状态标签均不能单独证明任务已完成。
3. **先下研再成文。** 每层先沿实际执行体、调用与分派向下取证，查清支撑本层陈述的关键条件、结果、上下游及边界，再返回本层组织图文。粗粒度线索可先列并随证据修订；重要未知继续查证或登记缺口。按 [颗粒度与复用](references/modules.md) 决定内联、独立模块或公共引用，逐项保留候选及去向。深度随证据需求调整，子模块全部成文不是前置条件。新增分支若影响本层真实性则继续必要取证，其余登记为后续待办。
4. **人工转交与暂停。** 本地取证 → 远端质疑 → 本地逐项补证回写 → 远端完整图文 → 本地核验、过闸并保存为待验收。完整稿默认用 UTF-8 Markdown 文件回传，以收到的原始文件核验，不靠模型重写。用 [协作与恢复](references/collaboration.md) 和 [转交模板](templates/remote-relay.md)。每次转交先保存当前稿，在 STATE 的当前焦点与下一步写清协作对象、等待材料及恢复动作，转交文字独立放进明显的 Markdown 代码块，然后结束本次执行，等用户带回相应输入再恢复。Goal 等自动续跑目标限当前自主阶段，以最近人工交接、验收或继续授权点为终点；无法可靠停止时报告限制，停止使用该模式。
5. **检查与验收。** 按 [图文与完成](references/completion.md) 核实远端实际输入、本地源码依据及适用四项闸门。未通过保持“梳理中”，具体反馈转交远端再核验；通过后记录拟完成类型、实际工具计算的指纹和核验基准，进入“待验收”。提出指向具体文件与版本的单一验收问题，保存现场并停止。用户对同一版本明确认可、机械条件有效才转正；异议或读者内容变化须回到梳理中复核。
6. **继续或阶段性交付。** 用户认可当前稿与授权下一项分别记录；未明确允许继续就保持暂停，一次回复可明确同时作出两项决定。新事实影响图、短注、出口或衔接时重开受影响模块，同步撤销整体完成与旧验收。先更新原始记录，再更新 STATE；报告确认、未决、检查与下一步，不只修改统计数字。整体完成另须所有模块（含总览）逐份验收，再对整体清单单独确认。

## 关键边界

- 事实、推断、待核实分开。没有检索命中不等于没有实现，处置和完成检查通过不能证明发现充分。
- 重要条件、事务、状态、异步、重试、权限、配置和外部副作用必须解释或登记缺口，不能标“琐碎”。薄包装需读到实际工作位置。
- 先内联，有独立解释价值再建模块；不按目录、函数数量、唯一父级或固定层数拆分。公共实现一份权威文档，各调用方说明输入、适用分支、实际可达出口与后继。
- 每模块一张 Mermaid 执行图，每个可见节点一条短注。只画有依据的执行关系；不为布局掩盖失败、状态或异步责任交接。Figma 仅是阅读场景，不主动调用、安装插件、截图验收。
- 总览是普通模块：节点为主体流程并引用入口序号，边和候选仅为跨流程交接。入口事实只放 COVERAGE，不强连独立流程。
- 本层完成、已证叶子、范围整体完成分别判断。父层核实子模块边界与本场景出口，不必等待全部内部细节；叶子须未处置数为零、限制为无且无待独立展开的重要阶段。
- 同仓串行，只维护当前有效稿。连续两轮对同一阻塞无新有效证据、核实修订或可执行调查路径时报告停滞，在已有明确授权内转向其他工作或交付限制；轮数不是通过线。
- 不修改业务代码；不自动发送材料。外发范围沿用用户授权，敏感值留在原处，只说明位置、规则与用途。普通补证自主完成，重大范围或确实缺少的授权才交用户决定。

## 工具与平台

核心为标准 `SKILL.md`、相对资源路径和 UTF-8 Markdown，适用于能加载本地 Skill 的 Codex、Claude Code、DeepSeek Harness 等环境；具体安装目录由所在 Harness 决定。`agents/openai.yaml` 仅是可忽略的 Codex 界面元数据，不影响主流程。

使用当前平台的文件读取、搜索、编辑和命令执行能力，不依赖某厂商 API、MCP、联网或子代理。搜索优先 `rg`，没有则用现有等价工具。命令中的脚本路径应解析为**本 Skill 安装目录**，知识库路径明确指定；不要假设当前目录就是 Skill 所在处。

```bash
python3 /实际Skill目录/scripts/check.py /实际项目/project-map
python3 /实际Skill目录/scripts/check.py /实际项目/project-map --json
python3 /实际Skill目录/scripts/check.py --fingerprint /实际项目/project-map/modules/模块.md
python3 /实际Skill目录/scripts/check.py --scope-fingerprint /实际项目/project-map
```

检查器只读，需 Python 3.10+ 标准库；也可使用满足版本的 `python` 或 Windows `py -3`，路径含空格时加引号。退出码：0 机械通过、1 失败、2 未验证。详见 [检查格式与人工替代](references/check-format.md)。没有命令执行能力或合适 Python 时，按同一清单人工核验并明确标记“脚本未执行”，不能声称自动通过。

## 交付

模块交付完整图文、源码依据、候选处置、确认与未决、下一步；汇报实际保存位置及状态。整体交付另附覆盖、范围限制、是否做过用户召回探针。分别列出发现、处置、完成以及机械通过／失败／未验证和人工核验结果。待办清零、双方认可或脚本通过均不构成绝对完整证明。
