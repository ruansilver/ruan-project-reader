# 双 AI 协作与恢复

本地是可读源码的一方；远端只能审所给材料。角色不绑定 Codex、Claude Code、DeepSeek Harness 或模型厂商。用户人工转交、反馈与最终验收，不替 AI 做普通源码调查。

每轮先说明当前模块或由真实执行关系关联的子网、范围、共同核验理由和本阶段交付物，再按顺序执行：本地事实与候选 → 远端质疑 → 本地逐项补证回写 → 远端完整当前稿 → 本地核验、适用闸门、保存 → 待用户验收 → 用户认可当前版本后正式完成 → 等待独立继续授权。发现影响本层真实性的新分支时继续必要取证，其余新模块登记为后续待办；范围由执行关系与证据需求决定。远端指出材料位置、影响和所需证据；有实质疑点则继续补证，证据充分时正常收束。本地不能用远端认可替代源码核验。

转交使用 [模板](../templates/remote-relay.md)，放独立明显代码块，块外面向用户。提示词默认普通文字；完整当前稿默认以 UTF-8 Markdown 文件回传，在块外列明文件。附授权内必要事实、证据内容、相关边界和完整当前未决，不能只给远端访问不到的本地路径。不要求反复传整库或历史，不自动向另一 AI 发送材料。已有外发授权直接沿用；没有时准备可审查草稿并说明缺口，保留尚未外发状态。

每次人工转交、用户验收、继续授权节点都结束本次自主执行，包括请求首次质疑、审补证和完整当前稿。先保存草稿，在现有 STATE 的当前焦点与下一步写清协作对象、等待的远端材料类型、文件/内容版本、核验依据、用户验收或继续决定及收到后的恢复动作，再交付独立代码块。只有用户带回相应输入后才恢复对应阶段；在模块“核验与下一步”等现有正文中记录收到的输入内容或可复核位置、逐项处理结果和尚存未决。

Goal 等自动续跑目标只覆盖当前自主协作阶段，最近的人工交接、验收或继续授权点就是目标终点。到达后按所在平台能够终止续跑的方式结束该目标，保存上述现场并等待；不得把“整个项目完成”设为跨越人工转交的自主目标。真实 Goal 行为未经实测须记未验证。若该模式不能可靠停止，报告限制并停止使用，必要时请用户手动中止作为故障处置，再改用可明确结束于交接点的方式；手动兜底不能作为自动暂停已验证的依据。

远端不可用时交付本地待审稿并等待。用户明确选择单 AI 时可继续本地调查和草稿维护，完成状态仍按 [完成条件](completion.md) 核验，协作输入缺失须如实保留。

## 完整稿接收与复核

用户将远端完整稿保存为 UTF-8 Markdown 文件，交回文件或可访问的本地路径。本地直接读原始文件或用文件工具复制到知识库外的隔离位置，先比对再覆盖当前模块。核验、diff、指纹都针对明确收到的内容，不把模型复述当原稿。转交提示词沿用 `~~~~text` 外层围栏，围栏本身不落入模块正文。

只能聊天粘贴时，先明确完整稿边界，以原始文本保真落盘并核对。截断、改写或无法证明一致时，记“传递保真未验证”，请用户核对落盘文件并暂停；确认后按同一核验流程处理。传递完整性与读者内容指纹分别检查，不能相互替代。远端另附本轮反馈背景、修改范围和待核实事项的简短转交说明，不写入知识库执行正文。

本地自己对比收到的完整新稿与当前稿，包括远端未声明的连带变化：

- 表达、布局反馈由远端组织新稿；先给本地的意见由本地转交。比对节点、边、条件、出口、引用、短注语义、源码依据及 Mermaid/适用检查；语义未变可不重查全仓，仍须对新版本适用核验和验收。
- 事实、遗漏分支、状态、调用和边界问题由本地调查受影响源码、有效配置、父子与公共引用，更新候选/未决及适用闸门。用户或远端猜测不是已证事实。
- 仅更新候选、未决、闸门、现场或派生汇总且不影响本层事实时，可保持读者版本；若揭示实质影响，即使哈希相同也须重开。限制值变化必须重新验收；影响无法判明则保留未验证继续补证。

核验未通过保持“梳理中”：给出位置、错误/遗漏、实际证据、影响、未决及改动范围，以独立转交提示词请求完整修订稿并暂停。沿用两轮停滞规则。核验通过保存完整稿、核验依据和闸门，记录拟完成类型与工具实际算出的指纹，进入“待验收”。

## 当前稿验收与继续

验收提问只问是否认可本轮当前版本，列文件名、各文件指纹前8–12位、拟完成类型、限制和未验证范围；完整64位值分别保存在各文件验收记录。不得心算、编造哈希或以短前缀做机器比较。例：“A.md（指纹前10位…）已按所列核验依据和限制交付，是否认可其作为当前版本？”提问后保存现场并结束执行。

在该明确问题后，“可以”“通过”可表示认可；“不错”“再看看”不自动视为认可。“可以，但第二张图改一下”是修改异议，退梳理中，保存实际回答，修订复核后对新稿重新提问。用户可向任一 AI 提意见，但正式修订稿都须经过本地适用复核。缺可信计算能力时保留待验收与未验证；恢复工具后重算并再次确认具体版本。

一次验收多份明确文件时，各文件各自保存拟完成类型、完整指纹、核验基准和用户问题/回答，可共同引用同一会话位置；仅认可部分就只转正这些文件。不在主文件集中维护子文件指纹。单纯认可不许可进入下一协作单位：在 STATE 当前焦点/下一步记录等待继续授权；明确“本稿通过，开始下一项”可分别生效，仅限明确的下一项，不推断后续连续授权、不建立范围授权或第二套审批库。

待验收期间，新入口/汇点即时登记。仅更新 COVERAGE/操作记录且不影响当前读者内容和结论，可保持待验收；影响本层边界或要改读者正文则先退梳理中。登记发现不等于获准启动下一单位。

## 恢复与逐项执行

同仓串行，不设计锁或并发合并。先读实际 Markdown、COVERAGE 和 STATE，核对等待事项与用户新转交的输入，优先处理尚未完成的验收/继续决定。重触发或中断恢复时，等待材料或相应明确决定尚未到齐就保持现场并结束执行；收到后才进入对应阶段。按原始记录派生待办并对账 STATE，汇总至少含四种状态模块数（含待验收）、待办数、阻塞数、入口数、汇点数、覆盖记录数；解析失败保留未知，不能填零。

每条任务开始前均复核当前源码、目标成果及落库状态。满足本项要求、无遗漏或中断遗留则完成该条，不重复拆解；不满足则补齐，必要时重开。模块已存在不能免除新调用场景的输入、分支、可达出口核实。

多条任务即使指向同一模块也逐条计数。先更新原始记录及关联处置，再派生 STATE；完成 A 不会自动消费 B。实际文件优先，不用旧摘要覆盖。只维护当前有效稿，通常在模块验收后换会话；意外中断先核对已保存内容和未落实修改。

本地交接提供实际路径、记录计数、完整未决及下一步；远端交接附它无法直接访问的正文。交付分别说明发现、处置、完成，区分通过、失败、未验证及人工核验。不存在的文件、未运行的工具、未得到的证据不可冒称成功。
